# PPT 动画质量规范

这份规范用于保证后续教案也能生成同一质量的 PPT 动画视频。

核心目标：

```text
不是字幕铺满画面，而是像老师讲课一样，让信息随着旁白逐步出现。
```

## 1. 文件分工

每个 lesson 目录至少需要这些文件：

```text
lessons/{lesson-slug}/voice.mp3       # 最终口播音频
lessons/{lesson-slug}/subtitles.srt   # 剪映导出的字幕时间轴
lessons/{lesson-slug}/scenes.json     # PPT 页面结构和动画节奏
```

职责分工：

- `subtitles.srt`：只负责字幕和总时长。
- `scenes.json`：负责画面页、每页起止时间、卡片内容、动画触发点。
- `templates/styles.css`：负责统一视觉风格。
- `src/generateHtml.ts`：负责 HTML 预览的逐步呈现动画。
- `src/renderSvgFrame.ts`：负责兜底 SVG 渲染，必须和 HTML 预览保持同样节奏。

## 2. 时间轴规则

正式视频必须优先使用真实时间轴：

```json
{
  "startMs": 162100,
  "endMs": 188600
}
```

不要在已有音频和 SRT 的情况下继续依赖 `durationSec` 估算整页时长。估算时长很容易在几页之后漂移，导致画面和音频不对齐。

规则：

- 每页都写 `startMs` 和 `endMs`。
- `startMs` 和 `endMs` 使用整条音频中的绝对毫秒。
- 页面顺序必须和音频顺序一致。
- `revealMs` 也使用绝对毫秒，不是相对本页时间。
- 如果口播里没有某一页内容，就不要保留这页。

## 3. 页面节奏

每页按这个顺序出现：

1. 页眉标签。
2. 主卡片外壳和页码。
3. 主标题。
4. 一句核心解释。
5. 旁白讲到关键词时，再出现对应卡片。

不要一开页就铺满所有信息。

推荐节奏：

- 标题页：问题先出现，背景解释后出现。
- 概念页：先给定义，再逐项补充。
- 对比页：左右两侧分开进入。
- 流程页：节点按讲述顺序点亮。
- 故事页：人物、行为、结果依次推进。
- 总结页：先给总标题，再逐条出现 takeaway。

## 4. 卡片内容规则

每个 `items[]` 只讲一个小点：

```json
{
  "tag": "01",
  "title": "提供交易",
  "body": "帮客户完成买卖",
  "revealMs": 52800
}
```

长度建议：

- `title`：中文 4-8 字最佳，尽量不超过 12 字。
- `body`：中文 6-16 字最佳，尽量不超过 22 字。
- 英文岗位名、公司名或术语过长时，优先改成中文标题，把英文留给口播或字幕。
- 一个页面只有一个子项时，不要硬标 `01`；能放进主卡就不要额外生成子卡。
- 每页卡片建议 2-4 个，不要超过 4 个。

不推荐：

```json
{ "tag": "01", "title": "Quant Researcher", "body": "负责研究 alpha 信号并寻找赚钱规律" }
```

推荐：

```json
{ "tag": "01", "title": "量化研究员", "body": "研究 alpha 信号" }
```

## 5. 视觉风格规则

当前项目采用“软纸面 + 低饱和色块 + 衬线大数字”的教学演示风格。

保留这些特征：

- 背景保持浅纸色，不要换成大面积深色。
- 卡片圆角控制在 8px 左右。
- 大页码使用衬线 italic，形成视觉锚点。
- 字幕固定在底部，只做听觉辅助，不做画面主体。
- 页面主信息在上半区，底部留给字幕和进度条。
- 不把 UI 卡片套在另一张卡片里。

避免这些问题：

- 一页只有大标题，没有信息结构。
- 卡片一开始全铺出来。
- 文字超出盒子。
- 英文单词被硬切到下一行。
- 单项页面被强行编号为 `01`。
- 后半段页面靠 `durationSec` 估算导致音画漂移。

## 6. 生成前检查

激活 lesson：

```bash
npm run lesson:activate -- chapter-name
```

检查场景质量：

```bash
npm run lesson:check-scenes -- chapter-name
```

构建 HTML：

```bash
npm run check
```

建议先渲染前 1-2 分钟试看：

```bash
RENDER_MAX_SECONDS=120 LESSON_OUTPUT_NAME=preview-2min.mp4 npm run lesson:render -- chapter-name
```

确认节奏没问题后，再渲染完整视频：

```bash
npm run lesson:render -- chapter-name
```

## 7. 人工抽查清单

生成完整视频前，至少抽查这些位置：

- 第 1 页：是否是问题导入，而不是字幕堆叠。
- 第 2-4 页：买方、卖方、类比等核心概念是否按关键词出现。
- 第 8 页之后：画面页是否仍然和音频对齐。
- 任意单主卡页：是否没有多余 `01` 子卡。
- 任意岗位/术语页：英文是否没有硬断行。
- 总结页：每条 takeaway 是否短而清晰。

如果某一页不美观，优先改 `scenes.json` 的标题和卡片文案，而不是直接改 CSS。
